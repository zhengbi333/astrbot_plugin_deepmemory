# alpha-0.14（2026-08-08）

## 变更

- **记忆隔离改为跟随 AstrBot 人格（Persona）**：
  - 插件不再维护自有的人格/记忆分区，直接读取 AstrBot 会话当前人格 ID（通过官方 `conversation_manager` 接口）作为记忆隔离键；在 AstrBot 中切换人格后，新记忆进入该人格的隔离空间，召回也按当前人格过滤。
  - 读取 AstrBot 人格失败或会话未配置人格时，回退 `general.default_persona_id` 指定的默认分区。
  - 移除插件内「记忆分区」管理：WebUI 删除该选项卡与用户绑定人格功能，删除 `/deepmem personas`、`/deepmem persona` 命令及相关 API；记忆库/手动新增等页面的人格字段现在对应 AstrBot 人格 ID。
  - 内部字段、数据库结构与对外桥接 API 保持兼容。

- **总结缓冲按会话独立计算**：私聊按用户、群聊按群分别累计未总结事件（以「会话 + 人格」为键），互不干扰；切换人格后缓冲自动分离。

- **`/reset` 同步清空未总结缓存**：插件监听全部消息事件，检测到 AstrBot 清空上下文指令（`/reset`、`/清空`、`/重置` 等常见形式）时，自动删除当前会话的未总结时间线缓存并记录日志。

## 修复

- **总结模型 60 秒超时**（此前日志 `error=` 为空 = `asyncio.TimeoutError`）：
  - 超时日志现在包含 Provider 类名与超时秒数，便于定位。
  - 默认超时从 60 秒提高到 120 秒（`summary.provider_timeout_seconds`）。
  - 超时/失败后自动依次尝试备用模型与当前会话模型（已在 alpha-0.12/0.13 建立），全部失败保留未总结时间线待下次重试。
- **多实例重复总结**：AstrBot 重载插件时可能短暂存在多个实例，总结去重集合改为模块级全局共享，避免同一会话被多个实例并发重复总结。

## 说明

- 若总结仍超时：优先检查 `summary.provider_id` 是否留空（使用当前会话模型，与聊天同模型），或更换更快模型 / 调大超时。
- 插件日志中 `获取 AstrBot 人格失败` 提示表示会话管理器不可用或未配置人格，属正常回退路径。
