# alpha-0.15（2026-08-08）

## 修复

- **总结持续超时（APITimeoutError: Request timed out）**：
  - 定位：`on_llm_request`（主链请求发出**前**）捕获用户消息时即触发总结，导致总结调用与主链对话**并发**请求同一个 API key——免费/中转接口对同一 key 的并发请求会限流排队，总结请求等待过久触发 SDK 超时；而单独对话（无并发）秒回，因此表现为"对话正常、总结卡死"。
  - 修复：**总结只在主链回复完成后（`on_llm_response`）触发**；主链请求前只捕获、不触发总结。群聊未提及消息的捕获仍按原逻辑。
  - 总结调用改为**流式优先**（`text_chat_stream`）：对慢速/拥挤 API 更稳（流式持续返回数据，不会因等待完整生成而超时）；流式不可用或失败时自动回退非流式 `text_chat` / 旧版 `text`。

## 新增

- **总结模型诊断**（WebUI 总览页「总结模型诊断」卡片）：
  - 一键测试总结模型调用链（主模型 → 备用模型 → 当前会话模型逐个尝试，流式优先）。
  - 显示每个候选的：来源、Provider 类名、耗时（ms）、SDK 超时配置、输出或错误信息，便于定位是模型慢、配置错还是网络问题。

## 说明

- 若诊断显示当前 Provider SDK 超时过小（如 30/60s），可在 AstrBot 的该 Provider 配置中调大 `timeout`，或把 `summary.provider_id` 留空使用当前会话模型。
- 插件自身的 `summary.provider_timeout_seconds`（默认 120）是外层保护，实际先超时的是 Provider SDK 层的 timeout。
