# alpha-0.81

## 阶段总结"拆半轮"修复——后台扫描拍点把"只有 user 的半轮"当完整轮总结掉

- **用户反馈（正确）**："我问'你在干嘛呢'，他回答完毕，这才算是第三轮"——第三轮的 bot 没有被总结，且 3/3 总结后又变成 1/3。
- **根因（证据链完整）**：
  - 09:45:07 user"你现在在干嘛呢？"写入时间线；
  - **09:45:16 后台扫描拍点（60 秒周期）**：未总结=9 条（到 09:45:07 user 为止）→ 轮数 3/3 达标 → **触发总结——此时第三轮只有 user，bot 回复还在路上**；
  - 09:45:17 bot"在实验室整理数据"、09:45:19 bot"小鹦鹉…"（缓冲拆条 0.8~4s 间隔）在总结进行中写入 → 不在快照、未被标记；
  - 09:45:42 总结完成（events=9, rounds=3, metadata 与 DB 实锤）→ **第三轮被"半个"总结掉（user 标记、bot 两条漏掉）**；
  - 尾巴只剩 bot 事件 → `_count_rounds` 对"首事件即 bot"算 1 轮 → 页面显示"1/3"（用户看到的假象：3/3 后又变 1/3）。
- **修复（0.81）**：新增 `_session_rounds_ready` **轮完整性守卫（仅私聊）**——未总结事件的**最后一段必须是 bot**（本轮已有回应）**且距最后事件 ≥2 秒**（收齐缓冲拆条尾巴）才允许触发总结；`maybe_summarize_session`（消息路径）与 `_scan_ready_sessions`（后台扫描）同步接入；**群聊按事件数触发、无 user/bot 配对概念，不套守卫**；`force`（手动"立即总结"）不受限（用户主动可含半轮）。
