# alpha-0.84

## 第 4 轮迭代：提炼前把同一人的连续消息合并

### 诊断（用真库快照，不靠猜）

上一轮体检时就发现 `timeline` **13 条里 10 条是 bot**。真链把原始数据打出来后原因很清楚——
机器人是**拆条发送**的，同一轮里的三句话被记成了三行：

```
[第1轮] 证毕: 你好
[第1轮] 阡墨: 嗯。
[第1轮] 阡墨: 晚上好。
[第1轮] 阡墨: 刚在看窗外。
[第2轮] 阡墨: 嗯。
[第2轮] 阡墨: 一万六到两万五。
[第2轮] 阡墨: 看渠道。
[第2轮] 阡墨: 要帮你找几个稳定的吗。
```

提炼模型看到的是"四次独立发言"，既啰嗦，又容易把一轮里的事拆碎成互不相干的片段。

### 修复

新增 `_compose_events_text()`：拼提炼输入时，**把相邻且同一位说话人的消息并成一行**。

| 规则 | 说明 |
|---|---|
| 合并范围 | **只并相邻且同一个人**（群聊里不同人挨着说话不会被并在一起） |
| 标点处理 | 上一句已有收尾标点就直接续上；没有则补一个空格，避免"CC2"这种粘连 |
| 轮次编号 | 仍以"对方说话"为新轮起点，轮数统计不变 |
| 空内容 | 跳过，不影响合并 |
| 开关 | `summary.merge_consecutive`（默认**开**）；关掉即恢复"一条一行"的旧行为 |

### 效果（真实数据 + 真实模型实测）

| | 合并前 | 合并后 |
|---|---|---|
| 行数 | 13 行 | **6 行（-54%）** |
| 字符数 | 239 字 | **162 字（-32%）** |
| 提炼结果 | — | 「证毕询问了RTX 5090显卡的当前价格，称实验室要购进一批设备；阡墨告知价格约一万六到两万五（看渠道），并答应帮证毕搜几个稳定渠道、晚点发给证毕。」 |

合并后的输入读起来就是一段正常对话，提炼出的记忆完整、准确、不碎片。

## 本轮遗留（后续轮候选）

1. `max_input_chars`（6000）在大对话量下会截断——合并省下的字数可以让更多历史进入一次提炼，
   后续可考虑"按轮数而非字数"截断，避免把一轮切两半。
2. 提炼产出的记忆目前只落一条"阶段总结"；将来可考虑拆成"事实/承诺/偏好"多条（与 storyteller 的
   `memory_write` 类型对齐），让召回更精准。
