# alpha-0.16（2026-08-08）

## 变更

- **总结改为「对话轮」计数**：
  - 轮次定义：用户连续发言段（可含多条消息）+ 机器人连续回复段（可含多条消息）算一轮；连续多条用户消息不再拆成多个事件计数。
  - `summary.trigger_event_count` / `summary.min_events` 语义由「事件条数」改为「对话轮数」，默认值调整为 8 / 4。
  - 触发日志与完成日志改为报告轮数与事件数。
- **每次总结生成一条综合记忆**（而非多条）：
  - 总结提示词改为输出单个 JSON 对象；把累计轮数的对话综合为一条记忆（content 为综合总结），保留摘要/类型/重要度/标签。
  - 兼容旧版数组输出：模型若仍返回数组，取第一条有效记忆。
  - 记忆 metadata 记录本轮涉及的事件数与轮数。
- **总结使用真实称呼（拟人化）**：
  - 总结输入按轮组织为 `[第N轮] 称呼: 内容`；用户侧使用用户昵称（如「用户」），机器人侧使用机器人名称（未获取到时用「我」）。
  - 提示词明确要求：总结正文必须使用双方称呼，禁止使用「用户」「机器人」「对方」等通称。
  - 生成记忆的主体/客体实体名称同步带上用户昵称与机器人名称。

## 说明

- **用户名称识别正常**（经数据库核查：时间线 user_name 无空值，如「用户」）。此前总结中没有称呼是提示词未使用称呼所致，本次已修复。
- 若机器人名称未显示（如「我」），是平台适配器未返回机器人昵称，可忽略或后续在人格配置中补充。
- 已在「设置 → 阶段总结」按需调整轮数阈值（当前配置文件为旧值 16，如需要可调低）。
