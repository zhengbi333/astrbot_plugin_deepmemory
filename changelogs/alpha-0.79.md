# alpha-0.79

## 修复：身份标识记忆文案与重要性 + 记忆库"删了还有"/计数不一致的认知问题

- **用户反馈**：① /reset 清空上下文、删除记忆库里一条记忆后，右上角仍显示"1 条记忆"，导入导出也看到 1 条，但记忆库列表显示"没有记忆"；② 第一次对话的三轮总结会变成"身份标识记忆"（"本条记忆旨在说明 xxxx"之类）。
- **排查结果**：
  - **"1 条" = 数据库里唯一一条 `memory_type=event` 的记忆，`lifecycle=decayed`（已衰减=归档）**——用户删的是 identity（身份标识）那条，剩下的这条（21:08 三轮总结，importance 0.1）在维护时被衰减归档；**记忆库列表默认只显示 `active`，所以"看不到"；但统计卡"记忆总数"（含归档）与导入导出（导出全部）都显示 1**——口径不一致造成"删了还有"的认知；
  - **"身份标识记忆"** = `ensure_identity_memory`（首次对话捕获时沉淀，非三轮总结产物）——使用了 0.42 的旧模板"{user_name}在{time}给我发了消息。这条消息旨在说明你知道对方叫{user_name}…"（用户配置里一直存着），且 **importance=0.85**（压过真实记忆、排检索最前）。
- **修复**：
  1. **旧模板识别忽略**：`identity_prompt_template` 含"旨在说明/给我发了消息"（旧特征）→ 忽略改用新默认"我记得{user_name}这个名字，用于确认我认识{user_name}，与亲密度、互动等无关。"（用户自定义新值不受影响）；
  2. **importance 0.85 → 0.3**：身份标识是轻标记（认得 TA），不再压过真实记忆；
  3. **存量迁移**（启动幂等）：`UPDATE memories SET content=新文案, importance=0.3, confidence=0.95 WHERE memory_type='identity' AND (content LIKE '%旨在说明%' OR content LIKE '%给我发了消息%')`；
  4. **记忆页一致性**：统计卡新增提示"默认只显示「活跃」记忆；另有 N 条已归档/衰减，可在「状态」筛选查看（删除某条后总数仍 >0 通常在这里）"（筛选项"活跃/归档/衰减/全部状态"本已存在）。
